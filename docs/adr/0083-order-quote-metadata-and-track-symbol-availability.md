# Order quote metadata and track symbol availability

A trade timestamp orders prices, but does not order changes to reliability metadata. A REST request can begin before a socket marks the held quote last-known and finish afterwards with the same trade timestamp and no warning.

Each provider's quote store maintains a local revision counter and the latest quote revision per symbol; availability transitions do not advance it. Stock query functions capture the revision before starting a REST request. A response with an equal trade timestamp cannot replace a symbol changed since that request began. Older trade timestamps remain rejected. A strictly newer timestamp still updates market values, but preserves a last-known warning from either the current quote or the response if the request was superseded locally. A request started after the change can apply equal-time corrections or clear a warning. This is local request precedence, not a new wire revision or a claim about provider event order. Cache hydration retains its strictly-newer rule.

Semantically identical quotes preserve object identity and do not notify quote subscribers. Comparison covers the fixed quote fields, including last-known and both day-range bounds. Equal-time corrections still notify only that symbol.

Transport health and symbol availability are independent. The additive core hook `useQuoteAvailability(symbol)` returns `available`, `recovering` or `unavailable`. Sending a subscription marks its symbols recovering unless a confirmed unavailable state already exists; that failure remains until a valid socket quote confirms recovery. Only a correlated, current terminal settlement changes still-recovering symbols to unavailable; unknown and capacity-refused symbols are unavailable too. A valid socket quote confirms availability, including an identical quote. A correlated, error-free snapshot containing the symbol confirms the subscription even when its older price is rejected: the gateway may reuse a cached stream quote after REST supplied a newer value. An older uncorrelated tick cannot confirm it. A tick arriving before the terminal reply remains valid. REST and hydration writes update values but cannot confirm a live subscription.

The additive `useQuoteWarning(quote)` hook supplies shared localized presentation for both apps. Initial recovery is control work, not a confirmed data failure, so it adds no financial warning or layout shift; unavailable data is labelled and muted until valid recovery. The provider's last-known warning remains independent.

Availability listeners are separate from quote-value listeners. There is no trade-age timer: a quiet stock remains available. Before subscribing, the absence of a known degradation defaults to available; SSR values therefore keep their existing presentation. Connection status still describes transport recovery. `Quote.lastKnown` independently describes the provider's held-price warning and must still be displayed even when a subscription is available.

This extends the frozen core API under the owner's financial-integrity assignment. The wire schema and protocol settlement semantics are unchanged. Both apps must consume the availability hook before the unavailable-data presentation fix is complete. Feed identity quarantine is a separate provider-scoped boundary (ADR 0077); it must reject incompatible data before any store write.
